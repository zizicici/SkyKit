# 高精度月球计算原型

这里保留独立原生计算验证及核心源码；App 已通过 [SkyKit 包](../../README.md)
接入相同核心和系数。原型验证工具不参与 App target。App 已移除旧库及回退，仅使用新引擎和独立标准折射函数。
目标是复现 ChineseCalendar 生成高精度月相时刻的计算方法，并验证同一星历能否支持实时找月亮。
最新的正确性审查、精度含义和接入条件见 [正确性与应用精度复核](accuracy-review.md)。

## 实现

- **星历**：JPL DE440s，保留 2000-01-01 至 2051-01-01（不含结束时刻）的太阳、地月质心、地球、月球数据。
  时间范围按 TDB 定义；额外保留两天边界数据供光行时计算使用。
- **裁剪**：直接复制原始二进制双精度 Chebyshev 系数，保留全部阶数，不重新拟合、不量化。
  原型验证用的数据文件是 **3,578,412 字节（约 3.41 MiB）**，其中还包括地月质心等必要依赖。
- **运行核心**：C++17 + C ABI。读取一次后只读使用，可以并发调用，没有 Python、联网或全太阳系数值积分的运行依赖。
- **标准模型**：使用 ERFA 2.0.1 中所需的 45 个 C 源文件。ERFA 派生自 SOFA，提供 IAU 2006/2000A 坐标变换等标准算法。
- **月相**：按作者文献中的光行时／行星光行差近似求日月地心视黄经差。
  黄经差中的章动项相消。四个主要月相通过有界二分搜索求解，数值终止条件为 0.1 毫秒。
  这个终止条件不是绝对天文精度声明。
- **照亮比例**：由光行时修正后的日、月、观测者几何关系计算，输出物理比例，不做 UI 的 0%/100% 取整。
  当前定义是地心几何照亮比例，不是实际亮度；不包含月食地影或站心照亮比例。
- **方向**：WGS84 站心位置、收敛检查的光行时、有限距离太阳引力偏折、观测者速度的光行差、
  IAU 地球姿态和地平坐标投影。新接口接受相对 IAU 2006/2000A 的实测天极偏移 dX/dY。
  返回无大气折射的方向；单次计算同时提供视 ICRF 和 WGS84 ENU 单位向量，供 AR 直接投影。
  角度接口仍保留。具体改进、适用条件和验证结果见 [计算方法说明](calculation-improvements.md)。

接口见 [native/lunar.h](native/lunar.h)。所有时间输入明确区分 TDB、TT、UT1，单位为距 J2000 的天数。
API 对超出范围、无效参数、无法在搜索窗口内找到事件返回错误，不外推，不静默返回伪造位置。
同一瞬间的 TT/TDB 差限制为 1 秒以内，UT1/TT 差限制为 864 秒以内，防止误传完整儒略日或秒数。
失败时保持输出缓冲区不变，不会以成功状态返回 NaN。调用期间必须保持 kernel 存活，释放不能与计算并发。
月相搜索包含起始时刻，容差为 0.1 毫秒；查找下一次同类月相时，应将起点移到上次结果至少一秒之后。

## 重现

需要 macOS、Xcode Command Line Tools 和 Python 3.12 或以上。依赖版本在 `requirements.txt` 固定。

```sh
cd prototypes/ephemeris
python3 -m venv .cache/venv
.cache/venv/bin/python -m pip install -r requirements.txt
.cache/venv/bin/python prepare.py --apple-check
.cache/venv/bin/python validate.py
```

`prepare.py` 校验下载文件的 SHA-256，生成裁剪数据并编译 macOS 动态库、基准程序，以及可选的 iOS arm64 静态库和模拟器程序。
下载、生成数据和编译产物均位于被 Git 忽略的 `.cache/`；可用 `SKYKIT_CACHE` 指向其他目录。
Python 与完整星历只用于准备和验证，原生运行时只需裁剪数据和计算库。

仓库包含固定的 Horizons 回归样本，正常验证无需访问其 API。刷新样本可执行 `horizons.py`；
该步骤会请求公开的固定测试坐标，包含地球自转时间差 DUT1，以免把不同时间输入误判为星历误差。
所有输入数据来源、摘要和尺寸都记录在生成的 `build-manifest.json` 中。
构建记录同时保存原生源码、ERFA 源码、对象文件、静态库、动态库和基准程序的 SHA-256。
验证在加载动态库之前核对这些摘要以及参考数据，拒绝使用陈旧构建；重新构建失败会移除旧构建记录。
请勿使用 `python -O` 或 `PYTHONOPTIMIZE`，验证脚本会拒绝关闭断言的运行方式。

模拟器已启动时可以增加原生性能测试：

```sh
.cache/venv/bin/python validate.py --simulator <UDID> --sanitizers
```

## 验证设计

1. **插值完整性**：对照完整 DE440s 与 JPLEphem，覆盖每个保留分段边界的前后、边界本身和随机日期，
   比较 59,880 组位置、速度。不同求值顺序和时间原点会产生毫米级的浮点差异，位置容差为 1 厘米。
2. **月相事件**：对照 ChineseCalendar 原始、未按分钟取整的 `TDBtimes.txt`，覆盖 2000–2050 年的
   2,523 次朔、上弦、望、下弦。统一在 TDB 中比较，避免闰秒／未来 UTC 预测影响。
   每次还验证以搜索结果为新起点时保持同一事件，以及从事件前一秒起搜索的行为。
3. **连续月相与方向**：与 Skyfield 使用同一份 DE440s 和同样时间输入的独立实现比较，
   包含 16 个指定样本和 200 个固定随机样本；同时比较月相角与照亮比例。
   另有 30 个非零极移样本，覆盖高纬度、极点和高海拔，防止只验证 xp=yp=0 的特殊情况。
4. **Horizons**：用独立的 DE441 结果检查视 ICRF 方向和地平坐标，匹配 DUT1。
   极点及极区地平坐标单独报告，并将视 ICRF 方向投影到同一 WGS84 基底后对照。
   [高纬度专项调查](polar-diagnostics.md) 已复现约 21 角秒差异的主要来源：两者局部基准不同，
   子午线差异在极区随纬度正切放大。精确匹配 Horizons 旧地球姿态变换仍未完成。
5. **边界与并发**：验证日期越界、损坏文件、非法参数、搜索范围限制，以及 8 个线程的 1,000 次并发调用。
6. **天极修正与向量接口**：核对 SOFA 官方固定矩阵示例，并在 168 个样本中与 Skyfield 对照有限距离
   太阳引力偏折，覆盖日食、时间边界、正负天极偏移、极点和不同经度；检查单位向量、极区连续性、
   非法参数不改写输出，以及 168 次并发观察计算。地球和其他行星引力偏折在此项对照中均排除。

实测结果保存在 [results.json](results.json)。比较差异不等于对真实月球的绝对误差；
多个实现共享 JPL 星历或标准模型，也不能视为完全独立的观测证据。

**评审结论：月相复现通过；统一 WGS84 基准后的 Horizons 方向对照通过；尚不能直接作为生产计算层替换。**
原始地平角度在非极区最大相差约 1.99 角秒，纬度 ±89° 约 21 角秒；
这组对照没有统一局部基准，不能直接判定为星历误差。统一投影后的 16 个样本最大差异约 0.00613 角秒。
保留原始地平角度验收 `not_met`，表示还未精确复现 Horizons 的整套变换；
现有的 2／30 角秒断言只用于监测回归。共同投影检查也不等于地球姿态的独立精度验证。
`results.json` 中的 `acceptance` 单独记录这项状态，与回归检查结果分开。

基准在原生循环内执行，排除 Python FFI，先预热，再取五批的中位耗时。
与此前使用的 Astronomy Engine、原 Go Mooninfo 的同进程对比另见 [三库性能对比](library-benchmark.md)，
该专项采用七批中位数，并分别覆盖连续日期与跨年分散日期。
模拟器依然使用 Mac 的 CPU，不代表真机速度、相机共存时的负载或耗电。
数据加载耗时包含文件读取与校验，但文件可能已在系统缓存中，不是冷启动 I/O 保证。

## 接入状态与模型边界

- **地球姿态**：新方向 API 接收 DUT1 所确定的 UT1、极移 xp/yp、实测天极偏移 dX/dY；
  旧角度接口相当于 dX=dY=0。Horizons 原有对照中的极移和天极偏移仍设为零。
  要直接复现 Horizons 原始地平角度，需要配套的 EOP、旧变换模型和当地子午线定义；
  仅补入公开极移数据仍有残差。详情与离线重现方法见 [调查报告](polar-diagnostics.md)。
- **时间数据**：Swift 包已实现 UTC/TAI 闰秒信息、TT/TDB 转换及带有效期的离线 IERS EOP 插值／降级；后续仍需维护资源。
  未来闰秒与地球自转无法通过固定星历预知。
- **坐标输入**：高度必须为 WGS84 椭球高；不能直接沿用普通海平面海拔。向量接口 ENU 与
  Core Motion 北／西／天顶之间需要 `(N, -E, U)` 转换。
- **覆盖范围**：本目录的验证数据仍为 2000–2050 年。App 已另行打包 1850–2149 年，iOS 26+ 通过一个苹果托管按需资源包扩展至 2649 年，iOS 15–18 仅使用内置范围；超出支持范围明确不可用。
- **观测修正**：已包含太阳对有限距离月球的引力偏折，尚未包含地球／其他行星引力偏折、大气折射，
  也未加入日长变化及岁差章动／极移变化率对站点速度的微小修正。低空实际大气条件仍限制方向精度。
- **天平动**：尚未实现。精确月面朝向需要相应的月球姿态 PCK 和框架定义；位置星历不能替代姿态数据。
- **App 集成**：Swift 包封装、资源生命周期管理、照片日期按需下载和坐标适配已实现；真机测量仍待完成。
  找月亮可保留低频天文计算、高频传感器投影的结构。

# 高纬度地平方向差异调查

结论：原来纬度 ±89° 附近约 20–21 角秒的方向差，主要发生在地平坐标基准转换，
不是 DE440 月球位置在高纬度失准。原验证直接比较了原型的固定 WGS84 东、北、天顶基底，
与 Horizons 按当地视恒星时定义的地平角度。这个比较没有统一局部坐标轴。

初次定位只增加了离线诊断、固定原始响应和回归检查，没有修改原生天文算法或加入拟合修正量。
本报告中的详细表格保留该次实验数值；后续太阳引力偏折与天极修正改进见
[计算方法说明](calculation-improvements.md)，最新模型结果在对应 JSON 中更新。
主要原因已用数据复现；精确复刻 Horizons 的旧地球姿态变换仍未完成，不能把这两项混为一谈。

## 1. 分离月球方向和坐标转换

新增 12 个诊断样本包含：同一日期、经度和海拔的 8 个纬度；原来南北极区样本；
一个日食日期样本。所有结果不含大气折射，UT1 使用对应 Horizons 输出的 DUT1。

| 对照方式 | 最大差异 |
| --- | ---: |
| 原型与 Horizons 的视 ICRF 方向 | 0.005426 角秒 |
| 将 Horizons 视 ICRF 方向投影到原型使用的同一 WGS84 基底后比较 | 0.005426 角秒 |
| 用 Horizons 自身视赤经、视赤纬、当地视恒星时重建其方位角／高度角 | 0.000003265 角秒 |

第一项检查月球相对观测者的天球方向。第二项固定同一投影变换，检查大差异是否来自坐标轴。
第二项与第一项基本相同是旋转保持夹角的预期结果，不能算第二份独立精度证据。
第三项确认了 Horizons 输出之间的具体关系，并非通过拟合月球位置降低误差。

旧的 16 个 Horizons 样本也新增了统一 WGS84 基底的检查；包含极点，最大差异约 0.006131 角秒。
这些数值是模型之间的比较差异，不是对真实月球方向的绝对误差声明。

## 2. Horizons 的地平角可以这样重建

请求 `QUANTITIES=2,4,7,45,49`：

- Q2：历元当天真赤道、真春分点下的视赤经 α、赤纬 δ。
- Q4：方位角、高度角。
- Q7：当地视恒星时 LAST，十进制输出的单位为小时。
- Q45：视 ICRF 赤经、赤纬，用于隔离天球方向。
- Q49：DUT1，用于统一地球自转时间。

取用户输入的**原始大地纬度** φ，以及时角 `H = 15 × LAST − α`（度），计算：

```text
E = −cos(δ) sin(H)
N =  cos(φ) sin(δ) − sin(φ) cos(δ) cos(H)
U =  sin(φ) sin(δ) + cos(φ) cos(δ) cos(H)
azimuth = atan2(E, N)
altitude = atan2(U, hypot(E, N))
```

12 个样本全部重建成功，差异约几个百万分之一角秒，符合接口十进制输出的舍入量级。
这是对已观测输出关系的实验确认，不声称检查过 Horizons 内部源码。

原型则先用 ERFA `c2t06a` 将视 ICRF 方向转到地固系，再投影到输入经纬度定义的 WGS84 ENU。
两者不只是在赤经上选了不同零点：**确定当地子午线的方法也不同**。
在中间真赤道坐标系中使用受极移影响的站点子午线，同时保留原始大地纬度，
与在地固系中始终使用完整 WGS84 法线和切平面，不是相同的变换。

Horizons 文档规定 LAST 与包含站点的历元真赤道子午线有关；其历元坐标使用经 EOP 修正的
IAU76/80，原型使用 IAU2006/2000A。文档也说明两者赤经原点约有 53 毫角秒差别，
因此不能直接混用 Q2 赤经与 ERFA 的恒星时。[官方定义](https://ssd.jpl.nasa.gov/horizons/manual.html)

## 3. 为什么高纬度会放大

在地固系与瞬时旋转坐标系之间，极移会让站点的有效经度发生小变化。
对小的极移角 xp、yp，一阶近似为：

```text
Δλ ≈ (xp sin λ + yp cos λ) × tan φc
```

λ 是经度，φc 是站点位置向量的地心纬度；xp、yp 与 Δλ 使用相同角度单位。
海拔为零时，`tan φc = (1−f)² tan φ`，WGS84 扁率 `f = 1/298.257223563`。
推导来自小角度变换 `x′ ≈ x − xp·z`、`y′ ≈ y + yp·z`，
再对 `atan2(y′, x′)` 求一阶变化。接近极点时，站点距转轴的水平距离趋近零，
很小的横向偏移也会导致很大的子午线角度变化。

固定 `2020-02-29 23:59:59 UTC`、东经 0°、海拔 0 米，仅改变纬度：

| 纬度 | Horizons LAST 相对赤道的子午线偏移 | 原型方位角 − Horizons 方位角 |
| --- | ---: | ---: |
| −89° | −19.984844″ | −20.013909″ |
| 0° | 0″ | −0.000397″ |
| 45° | +0.348840″ | −0.252912″ |
| 80° | +1.978366″ | −1.922492″ |
| 85° | +3.987252″ | −3.942508″ |
| 89° | +19.985098″ | −19.950128″ |
| 89.9° | +199.882555″ | −199.849848″ |

对非零、非极点的六个纬度，子午线偏移除以 `tan φc` 得到约 **0.351194″**，
系数变化小于 0.0001″。这是保持日期和经度不变的受控实验，支持极移／中间坐标轴倾斜的放大机制。
这里的系数只是诊断量，没有用于修正原生输出；不同日期、经度的系数也不同。

表中的子午线偏移不是方位角误差的通用计算公式；方位角还取决于目标方向和完整坐标变换。
在极区，这项偏移成为主要贡献，因此数值接近。

## 4. 公开极移数据能解释多少

使用 JPL 固定归档 `260921_180005-marge_eop2.long`，按 **TAI** 而不是 UTC 插值，
该历史时刻得到 yp 约 0.355254″。把 WGS84 站点通过极移矩阵转到 TIRS 后计算有效经度：

- 北纬 89°：预测子午线偏移约 20.216368″，与 Horizons 的 19.985098″ 相差 0.231270″。
- 北纬 89.9°：预测约 202.197900″，与 Horizons 相差 2.315345″。

因此公开极移数据解释了约 99% 的主要偏移，但**没有精确复现 Horizons 的有效子午线**。
剩余量仍随纬度放大，不能当作月球星历误差，也不能靠把极移参数设为非零就宣称全部解决。

EOP2 产品采用 ITRF2008/ICRF2 定义；Horizons 文档描述的是经配套 EOP 修正的
ITRF93／IAU76-80 变换。模型、修正项和数据版本必须配套，发布日期接近不代表可以直接互换。
残余的具体分配还需要精确匹配 Horizons 所用变换；本次没有证明每一毫角秒分别来自哪里。
[EOP 产品说明](https://eop2-external.jpl.nasa.gov/)，
[固定数据归档](https://eop2-external.jpl.nasa.gov/eop2/260921_180005-marge_eop2.long)。

## 5. 正好在极点时

同一北极样本原始方位角差约 93.7844°，但统一局部坐标轴后方向差仅 0.003310″。
它不是月球突然错了九十多度：精确极点处经度／北方向没有唯一自然选择，
不同的参考子午线会给同一方向完全不同的方位角。此处不能使用上面的一阶正切公式。

原型在 ±90° 仍由输入经度显式选择 ENU 基底，避免直接对极小的水平投影求“自然北”。
AR 后续应保持统一的局部基底或三维向量，并明确极区真北基准；不能拿另一个约定下的
方位角做经验补偿。天文方向与传感器姿态必须在同一坐标系相接。

## 6. 验证状态与重现

保留旧的原始 Az/Alt 差异和 `horizonsSubarcsecondHorizontal: not_met`，避免把尚未匹配的
Horizons 完整地平输出标为通过；新增 `horizonsCommonFrameDirection: passed`。
旧检查本身不能再用来判断星历是否达到亚角秒精度。生产接入仍需 UTC/EOP 生命周期及真机验证。

准备环境与构建按 [README](README.md) 执行，然后：

```sh
python polar_diagnostics.py
python validate.py --output results.json
```

如构建目录位于其他位置，保持相同的 `SKYKIT_CACHE` 环境变量。诊断运行不访问网络。
